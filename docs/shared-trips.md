# 다인 여행 공유 정산

## 이번 버전

- 여행 이름과 참여자 이름 2~20개를 입력하면 여행이 생성된다. 참여자 수는 이름 개수로 결정되며, 생성 후 참여자 구성 변경은 지원하지 않는다.
- 256비트 난수 공유 링크가 여행의 조회·편집 권한이다. DB에는 토큰의 SHA-256 해시만 저장한다.
- 참여자는 링크에서 자기 이름을 선택한다. 선택은 서버 세션과 이 브라우저에 기억되며 본인 인증이 아니다. 링크를 아는 사람은 다른 이름을 선택하거나 모든 지출을 수정할 수 있다.
- 각 지출의 결제자는 여행 소속 참여자만 지정할 수 있다. 내 이름(작성자)과 결제자는 서로 다를 수 있다.
- 모든 지출은 전체 참여자가 균등 부담한다. 지출별 분담자, 회원 로그인, 소유자 권한, 변경 되돌리기, 웹소켓 동기화는 포함하지 않는다.
- 금액은 통화별 정수 단위다. USD 센트 입력은 지원하지 않는다. 외화 환산은 저장 시 수행하며, 금액·통화를 변경하지 않는 수정에서는 당시 원화 환산액을 유지한다.
- 지출 목록은 30초마다, 또는 새로고침 버튼/탭 복귀 시 갱신한다. 같은 지출을 동시에 변경하면 버전 검사로 덮어쓰기를 방지한다.
- 변경 이력에는 선택한 작성자 이름, 등록·수정·삭제 시각, 변경 전후 스냅샷을 저장한다. 화면에는 최근 50건을 표시한다.
- 홈에서 방문자마다 별도 샘플 여행을 생성한다. 최근 여행은 이 브라우저에서 만든 링크 최대 8개이며 계정 기반 여행 목록이 아니다.

## 정산

원화 환산 금액 합계를 참여자 수로 나눈다. 나머지 원은 참여자 등록 순서대로 1원씩 배정한다.
각자의 결제액에서 부담액을 뺀 결과가 양수이면 받을 사람, 음수이면 보낼 사람이다.
남은 금액이 큰 사람부터 연결해 최대 N-1번의 송금으로 잔액을 모두 없앤다. 모든 입력에서 송금 횟수의 수학적 최솟값을 보장하는 알고리즘은 아니다.

예: 현호 20만원, 민수 10만원, 지영 0원 → 각자 10만원 부담 → 지영이 현호에게 10만원 송금.

## 로컬 실행과 검증

PHP 8.1 이상, Composer, MySQL 또는 SQLite가 필요하다.

~~~sh
composer install
cp .env.example .env
php artisan key:generate
# .env에서 DB 연결과 EXCHANGE_API_KEY 설정
php artisan migrate
php artisan serve
vendor/bin/phpunit
~~~

홈에서 예시 여행 체험을 선택하면 외부 환율 API 없이 KRW 샘플로 전체 흐름을 확인할 수 있다.
실제 외화 등록에는 유효한 API 키가 필요하다. 키는 config/services.php에서 설정하며 서비스는 config('services.exchange_rate.api_key')를 사용한다.

테스트는 메모리 SQLite를 사용한다. 여행 분리, 이름·결제자 검증, CSRF, 동시 수정 충돌, 감사 이력, 기존 데이터 이관, 링크 교체, 정산 합계 보존, 외화 환산 실패를 검증한다.
운영 MySQL에서의 배포 검증은 별도로 수행해야 한다.

## 기존 운영 데이터 이관

새 마이그레이션은 원본 지출을 삭제하거나 환산액을 변경하지 않는다.
기존 지출을 '기존 여행 기록' 여행에 연결하고, 나/동생과 기존 결제자 이름들을 참여자로 만든다.
지출하지 않은 동생도 포함되므로 원래의 2인 정산 의미를 유지한다.
기존 여행 접근 링크는 자동 공개하지 않는다. 관리자만 아래 명령으로 링크를 발급한다.

~~~sh
php artisan trips:legacy-link
~~~

재실행하면 기존 링크는 무효화된다. 링크는 비밀번호처럼 보관하고, 공개 README·채용 데모에 개인 여행 링크를 올리지 않는다.
세션에 기억된 이름만으로는 무효화된 링크에 다시 접근할 수 없다.

기존 환율 오류 복구 명령은 동일 여행·동일 통화의 정상 행만 참고한다.
평균 환율은 추정치이므로 실제 여행 당시 환율로 확정 복구하는 것과는 다르다.
DB 백업 후 아래 결과를 검토하고, 복구가 필요한 경우에만 실행한다.

~~~sh
php artisan expenses:fix-krw --dry-run
# 검토한 운영 담당자가 필요 시 실행:
# php artisan expenses:fix-krw
~~~

## 배포 순서

1. 운영 DB와 기존 코드, .env를 백업하고 비운영 복제 DB에서 마이그레이션을 검증한다. MySQL의 DDL은 전체가 하나의 트랜잭션으로 되돌아가지 않는다.
2. Apache 기본 인증이 유지된 상태로 유지보수 모드에 들어간다: php artisan down
3. 코드를 배포하고 composer install --no-dev --optimize-autoloader를 실행한다. 운영에서 예시 시더나 migrate:fresh를 실행하지 않는다.
4. .env에서 APP_URL=https://spend.haenoya.com, APP_DEBUG=false, SESSION_SECURE_COOKIE=true, DB 연결과 API 키를 확인한다. 기존 APP_KEY는 유지한다.
5. php artisan migrate --force, php artisan config:cache, php artisan view:cache를 실행한다. 필요 시 PHP 런타임 캐시를 갱신한다.
6. php artisan up 후 기존 전체 API /api/expenses, /api/categories와 잘못된 여행 링크가 404인지 확인한다. 기존 API를 남긴 채 기본 인증을 해제하면 안 된다.
7. trips:legacy-link로 운영자에게만 개인 여행 링크를 발급하고 기존 합계와 이름을 확인한다.
8. 기본 인증 해제는 웹 서버에서 별도로 진행한다. 이후 시크릿 브라우저로 홈 → 예시 여행 → 이름 선택 → 등록/수정/삭제 → 정산을 확인한다.

새 구조는 다인 여행이 생긴 후 이전 스키마로 안전하게 되돌릴 수 없어 자동 down()을 의도적으로 거부한다. 롤백이 필요하면 유지보수 모드에서 백업한 DB와 코드를 함께 복원한다.
저장소에는 EC2 접속 정보나 자동 배포 설정이 없다. GitHub 업로드만으로 운영 사이트가 변경되지는 않는다.

## 링크 방식의 운영 제약

- 링크가 유출되면 해당 여행의 전체 편집 권한이 유출된다. URL이 접근 로그·브라우저 기록에 남을 수 있으므로 로그 접근도 제한한다.
- 공유 화면에는 외부 CDN·분석 스크립트가 없고 no-referrer, no-store, noindex를 적용한다. 검색 제외는 접근 권한 검사를 대체하지 않는다.
- 생성은 IP당 분당 10회, 여행 접근은 분당 120회로 제한한다. 지속 운영에는 데이터 보존/삭제 정책과 추가 남용 방지 수단을 운영 규모에 맞춰 추가한다.
- 이름 선택은 협업 편의를 위한 표시다. 실제 인증·권한 분리가 필요할 때 로그인과 여행 멤버십을 도입한다.
